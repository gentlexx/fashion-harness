# 数据来源、可追溯性与限制

[English](data-provenance-and-limitations.md) | 中文

## 1. 当前数据策略

当前实现围绕小规模、可追溯研究建立对象链：

`ResearchTask → Source → Sample → Evidence → AnalysisRun → TrendCluster → DesignOpportunity`

`Source` 记录来源身份和访问信息，`Sample` 保存被分析的样本，`Evidence` 保存可供人工复核的证据。分析结果不应脱离这些对象被包装为实时市场事实。

## 2. R0 种子的定位

仓库包含一个用于演示对象关系和流程的 R0 种子。公开化调整对无法稳定复核的精确值进行了降级：相关证据标记为待复核，易变的精确值不再以已验证事实出现；可推导的价格结论保留为派生结论，并明确其复核状态和依据。

R0 不是完整数据集，不代表实时市场全景，也不构成商业预测。真实品牌页面或 URL 仅用于来源可追溯性示例，不表示品牌合作、授权或背书。

## 3. 当前已知限制

以下限制属于公开边界，不能通过文案省略：

1. **分析引用的存在性与归属未完全验证**：分析对象可能引用研究对象，但系统目前没有在所有路径上强制验证目标存在且属于同一项目；
2. **没有完整 Brief 修订界面**：当前界面不能覆盖所有 Brief 字段、版本差异和完整修订体验；
3. **Improvement 候选不保证强一致**：`ImprovementItem` 是改进候选，不保证与所有来源对象强一致，也不会自动修复业务状态；
4. **Evaluation 依赖 Git 检出**：部分评估证据依赖仓库和 Git 上下文，不适合被描述为任意部署环境均可独立运行；
5. **全仓文档债务仍然存在**：T-06 已通过应用构建、Fashion 定向测试、启动和浏览器主链，但全仓 translation-pairing 与 Markdown 链接检查仍会报告保留的上游文档指向候选包排除的内部路径。

## 4. 隐私和凭证边界

- 仓库不应包含真实 API Key、访问令牌或个人凭证；
- `.env.example` 只提供空变量名，不提供可用值；
- 运行产生的本地 storage、settings、credentials 和用户数据不属于公开材料；
- 不使用真实客户 Brief、未授权对话或个人隐私作为演示内容；
- fictional walkthrough 明确使用虚构数据，不能当作真实用户证据。

## 6. 长期数据愿景不是当前能力

长期规划包含 Fashion Dataset、Fashion Ontology、设计师反馈、评测体系和模型改进闭环。但当前仓库尚未实现大规模采集授权流程、完整数据治理、垂直模型训练或真实市场效果回流，因此不会用这些规划替代当前证据。
