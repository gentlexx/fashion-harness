# 案例数据与证据边界

## 案例材料可以说明

- 当前公开文档如何使用代码中的领域名称；
- Brief、研究、分析、设计、审核、交付、反馈和评估之间的预期关系；
- 为什么要恰好三个、彼此区分的设计方向；
- 为什么内容变化后需要重新确认批准；
- 为什么“尚未观察到结果”比填写没有真实来源的商业指标更诚实；
- 为什么改进候选需要人工判断，而不是自动写回业务状态。

## 案例材料本身不能证明

- 任何真实品牌、市场、趋势、用户或客户结论；
- 真实服装设计师已经使用或认可该产品；
- 真实销量、转化率、预测准确度或商业效果；
- JSON 可以导入当前应用或完全符合内部 schema；
- Agent 已经具备 Fashion 写权限或多 Agent 自主执行能力；
- 项目所有者独立手写了所有实现代码。

## 已由独立工程验证补充

案例材料不是工程验证凭证；独立验证已在最终应用提交上完成应用全量构建、typecheck、46 个 Fashion 定向测试文件／284 个测试、全新运行目录启动、HTTP 200、人工浏览器主链检查和六张截图。准确范围和仓库保留失败见[验证与证据](../../docs/fashion/validation-and-evidence.zh.md)。

## 仍待真实用户验证

1. 设计真实的服装设计师试用任务、知情说明与反馈记录；
2. 验证设计师是否能够理解证据、完成审核并获得实际工作价值；
3. 将真实用户观察与合成案例数据完全分开保存和表达；
4. 在获得真实证据前，不声明满意度、效率提升、销量或商业效果。
